一、推理服务相关学术论文

Pallas: A Proactive KV Cache Migration Framework for LLM Inference in AI-RAN
论文链接: https://arxiv.org/abs/2608.16477
发布时间: 2026-08-17
类别: cs.LG
论文总结: AI-RAN 将 LLM 推理拉近移动用户，但蜂窝切换会使活跃请求与推理状态分离：用户附着到目标基站时 KV 缓存仍留在源端。Pallas 提出主动 KV 迁移框架，在切换前预测目标并并行准备推理状态：将 token 序列分为稳定历史前缀和演化后缀，目标侧通过本地 prefill 重建前缀，源侧流式传输后缀的 KV 块。切换时目标组装完整 KV 并本地恢复解码，仅有未完成的准备工作计入服务中断时间。在线调度器基于移动预测和运行时遥测选择预取窗口。在三种 LLM 和 100-500 Mbps 互联链路上，vLLM 原型将平均中断时间降低 2.28-89.68 倍，平均 token 间延迟降低 16.0%-50.0%。
亮点: 首次将 KV 缓存迁移与蜂窝切换并行化，用前缀重建加后缀流式传输把切换中断从串行转为重叠。

二、KV Cache 复用相关学术论文

KV-Pipe: On the Relation Between KV Sharing and Pipeline Parallel Efficiency in LLMs
论文链接: https://arxiv.org/abs/2608.15943
发布时间: 2026-08-16
类别: cs.DC
论文总结: 流水线并行广泛用于 LLM 训练，但效率常受限于阶段不均衡和流水线气泡。跨层 KV 共此此前主要被研究为推理时减少 KV 缓存开销的机制，未考察其如何重塑流水线负载。KV-Pipe 提出阶段感知的 KV 共享机制，将 KV 复用转化为流水线均衡的控制旋钮：从尾阶段开始，以尾优先顺序将选定注意力层转换为跨层 KV 共享，迭代地消除当前瓶颈，将 FLOPs 不均衡比驱向 1。该过程离线执行，仅需流水线划分和每层 FLOPs 估计，运行时开销可忽略。在多种流水线配置下，KV-Pipe 持续提升利用率和吞吐，训练 MFU 最高提升 9.2%，迭代时间最多降低 9.8%，流水线并行度越高增益越大。同一 KV 共享机制还能减少推理侧 KV 缓存增长和冗余投影，提升长上下文解码吞吐。
亮点: 将 KV 层布局从单纯的推理优化手段提升为联合优化训练流水线效率与长上下文推理的系统-架构自由度。

三、推理 Infra 相关学术论文

A CXL Memory Rack for Multi-Turn LLM Serving
论文链接: https://arxiv.org/abs/2607.18141
发布时间: 2026-08-05 (v3)
类别: cs.DC
论文总结: 长上下文、多轮和 Agentic LLM 负载越来越多地复用已处理上下文，使 KV 缓存复用成为减少冗余计算的关键。但复用将瓶颈转移到存储和服务可复用 KV 状态的内存层。GPU HBM 和主机 DRAM 成本过高，难以扩展到 TB 级共享上下文容量。论文提出 HyMCache，面向多轮 LLM 服务的 CXL 内存机架，使用 CXL 混合内存（少量设备内 DRAM 加大容量 SSD 后备）构建。利用多轮 KV 访问读主导、可预测、仅追加的特性，HyMCache 用请求级前缀预取和机会写缓冲将延迟关键读暂存于设备 DRAM，实现 SSD 级成本下 DRAM 级的 KV 缓存效率。在真实 CXL-HM 原型上，相同 DRAM 预算下 HyMCache 单节点服务性能为本地 LMCache 的 3.0 倍，PD 分离下为 1.45 倍；相比 1TB 分布式 DRAM 的 Mooncake，性能低约 30% 但 DRAM 用量仅 1/16。
亮点: 用 CXL 混合内存在 SSD 成本下逼近 DRAM 级 KV 复用效率，将共享上下文容量的 DRAM 需求降低 16 倍。

五、Vibe coding 最佳实践

实践: 每次编码会话前做上下文预加载，别让 AI 从零开始猜你的项目
来源: https://www.kunalganglani.com/blog/vibe-coding-best-practices-2026
问题描述: Vibe coding 中最常见且最浪费的做法是直接开始提示，不做任何上下文准备。AI 工具每次会话开始时对你的项目一无所知，如果不主动喂入相关代码文件、架构文档和命名约定，AI 只能靠猜，导致生成的代码与现有系统风格冲突、状态管理方式不一致、引入不存在的依赖。据 Vibe Code Wiki 分析，缺少上下文预加载时标准 CRUD 功能开发速度慢 2-5 倍，样板代码多 40-60%。
具体做法: 在项目根目录维护一份活的 CLAUDE.md（或等价配置文件），包含技术栈、关键架构决策、命名规范，以及一个"不要做"的清单（这个反向清单比正向清单省更多返工）。会话开始时该文件自动加载并全程驻留上下文。每次调试发现的约束都追加进去，文件会随项目成长越来越长。关键原则是：先给 AI 看你的世界，再让它动手。这比一次性发一个长提示可靠得多——后者生成的代码看似完美，实则可能同时混入三种不同的错误处理模式和两套数据库连接方式。
