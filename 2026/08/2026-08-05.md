Efficiency and Cost Alignment in Batched LLM Serving via Resource-Fair Scheduling
论文链接: https://arxiv.org/abs/2608.02244
发布时间: 2026-08-03
类别: cs.DC, eess.SY
论文总结: 在批处理 LLM 服务中，长短请求共享同一个解码批次时存在资源分配不公问题：一个批次步骤的耗时主要由最大活跃 KV-cache 占用决定，短请求与长请求同批时，其延迟和 GPU 资源消耗与其自身 token 工作量严重不匹配。本文将这一现象形式化为资源公平调度问题，建立将批次内资源公平性与系统吞吐关联的数学模型，提出约束解码进度差异（等价于 KV-cache 占位差异）的公平条件，并据此设计 ISJL 参数化混合批处理算法，证明其达到 3/4 的全局竞争比下界。实验表明，ISJL 在 FCFS 的批处理外部性与 LJF 的成本对齐之间取得平衡，在维持高吞吐的同时让按 token 计费的收入与批处理成本更好地对齐。
亮点: 把批处理服务中"长短请求互相拖累"这一被忽视的公平性缺陷，形式化为可证明竞争比的调度问题，并直接对接按 token 计费的商业模型。

二、KV Cache 复用相关学术论文

RestoreKV: Recovering Full-Cache Behavior Under Aggressive Query-Agnostic KV Cache Eviction
论文链接: https://arxiv.org/abs/2608.01247
发布时间: 2026-08-02
类别: cs.CL, cs.LG
论文总结: 查询无关的 KV cache 驱逐策略可以一次压缩上下文、复用于任意后续查询，但在紧凑预算下性能会急剧塌陷。现有方法主要改进保留哪些原始 KV 对，本文提出 RestoreKV，在同一总 KV 预算下用学习式恢复来补充选择式压缩。核心洞察是：虽然驱逐丢失的信息是上下文相关的，但生成其紧凑补充的机制可以跨上下文共享。上下文预填充后，由若干 restore token 经一次 LoRA 适配的前向 pass 对完整 KV 做注意力，生成紧凑且上下文相关的恢复 cache。基础重要性评分与驱逐规则不变，适配器在后续查询和解码中均关闭。RestoreKV 通过冻结的完整 cache 模型自蒸馏训练，仅优化 0.4% 参数，无需任务特定调优。在 Qwen3-4B 上覆盖五种基础驱逐方法，5% 预算时将 KVzip 在 RULER-4K 上从 38.2 提升至 73.2；配合 KVzip+ 在 16 倍压缩下达到 86.4 的 RULER 准确率，额外一次性 cache 构建开销不足 0.5%。
亮点: 不改动驱逐规则、只额外注入一次极轻量 LoRA 生成的"恢复 cache"，即在极端压缩比下大幅逼近全 cache 质量，复用性极强。

三、推理 Infra 相关学术论文

Energy-Efficient LLM Serving via Disaggregated Attention-FFN and Flexible Frequency Scaling
论文链接: https://arxiv.org/abs/2608.01891
发布时间: 2026-08-03
类别: cs.DC, cs.AI
论文总结: LLM 服务为满足严格 SLO 往往让 GPU 全频运行，能耗居高不下。现有节能方法只在请求或推理阶段级别调节频率，忽视了 Attention 与 FFN（A/F）在频率敏感性上的算子级差异。本文发现 A/F 的能耗最优频率不同且随推理阶段、负载和系统配置变化，但运行时多变性与独立 A/F 频率控制会带来巨大搜索空间和通信开销。为此提出 AFlex 框架，联合优化分离式 A/F 服务的资源供给与 GPU 频率调节：全局调度器决定 A/F 资源分配与频率，算子级动态电压频率调节（DVFS）控制器逐算子调频，并引入带动态微批深度与自适应请求批处理的交错 A/F 流水线以减少气泡。AFlex 在 SGLang 上实现，用 Qwen3-32B 和 Mixtral-8×7B 在 A800 上基于生产级对话与编码 trace 评测，每 token 能耗较先进分离式服务降低最高 49%，较调频系统降低 48%，同时满足 TTFT 与 TPOT 的 SLO。
亮点: 在 SGLang 中落地算子级 A/F 分离加 DVFS，把"LLM 推理也该像 CPU 任务那样精细调频"变成可上线的工程方案。

五、Vibe Coding 最佳实践

实践：Vibe Coding 必做的安全审查清单，别让 AI 生成代码默认"安全"
来源: https://appwrite.io/blog/post/vibe-coding-security-best-practices
问题描述: Vibe coding 让开发提速，但 AI 模型基于训练模式生成代码，不会对安全性负责。它极易输出"能跑但带洞"的实现，比如登录函数把密码明文入库、或前端直接拼接用户输入导致注入。开发者若默认 AI 产物正确就直接合入，等于在不知情中引入认证绕过、数据泄露等高危漏洞。
具体做法: 第一，逐行审查 AI 生成代码，理解每个函数用途，遇到看不懂的逻辑先研究测试再集成；第二，强制使用成熟认证范式（如 bcrypt/argon2 哈希、框架内置会话），拒绝 AI 给出的自造密码校验；第三，对用户输入一律参数化查询并做服务端校验，不要信任 AI 默认的前端校验；第四，把密钥与敏感配置放进环境变量或密钥管理器，绝不让 AI 硬编码进源码；第五，为每个 vibe coding 产物编写并跑通安全测试（注入、越权、限流），把它当作任何第三方代码一样对待。
