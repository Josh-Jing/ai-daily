一、推理服务相关学术论文

DualDecoder: Accelerate Long Context LLM Inference by Predictive Prefetch
论文链接: https://arxiv.org/abs/2607.26475
发布时间: 2026-07-29
类别: cs.DC
论文总结: 长上下文推理面临严峻的显存墙问题，KV Cache 随上下文长度和并发数线性增长。现有稀疏 KV 方案将大部分 KV 卸载到主机内存，但检索管理所需的辅助状态本身会占据大量 GPU 显存，成为高并发下的新瓶颈。本文提出 DualDecoder，其核心洞察是：解码下一个 token 所需的关键 KV 条目，可以通过前一个推测 token 精确预测。基于此，DualDecoder 设计了双 token 解码流水线，将 KV 检索与解码计算重叠执行，并采用层感知传输调度和层级内存管理器，几乎消除了辅助状态的显存开销。实验表明，在保持解码延迟和模型质量的前提下，解码吞吐量最高提升 2.62 倍。
亮点: 通过"推测 token 预测关键 KV"实现检索与解码重叠，以接近零显存开销消除稀疏注意力的辅助状态瓶颈。

二、KV Cache 复用相关学术论文

InferScale: GPU-Native KV Injection for Personalized LLM Serving
论文链接: https://arxiv.org/abs/2607.27090
发布时间: 2026-07-29
类别: cs.DC, cs.LG
论文总结: 个性化 LLM 服务中，用户的长对话历史和记忆档案需要反复注入 prompt，迫使引擎不断重复预填充相同内容，导致 TTFT 随检索预算增长而飙升。本文提出 InferScale，一种 GPU 原生记忆系统，用可复用的 KV 状态替代重复预填充。系统预计算每条记忆事实的 KV 表示并连同语义嵌入存储在 GPU 上，服务时按需检索并直接注入 vLLM 的分页缓存。为兼容 RoPE 旋转位置编码，提出 Chunked RoPE 在存储时保留旋转前的 key，注入时再施加目标位置；并设计 Context-Window Encoding 缓解独立编码丢失跨事实上下文的问题。在 LoCoMo 基准上，k=50 时 TTFT 降低 72%-79%，吞吐量提升 3.7-4.5 倍。
亮点: 通过 vLLM KV-connector 接口实现"记忆事实级"KV 注入复用，无需修改引擎或微调模型，将服务延迟与检索上下文大小解耦。

三、推理 Infra 相关学术论文

SpecBox: Speculative Sandbox Scheduling for Efficient LLM Agent Serving
论文链接: https://arxiv.org/abs/2607.23933
发布时间: 2026-07-26
类别: cs.DC, cs.AI, cs.LG, cs.PF
论文总结: LLM Agent 越来越依赖 MCP 协议调用隔离的外部沙箱，分离式沙箱部署在资源利用率和交互尾延迟之间存在根本矛盾：长期预留沙箱带来过高内存开销，而按需懒启动则产生严重冷启动惩罚。本文提出 SpecBox，一个围绕推测性沙箱预分配构建的运行时。核心机制包括：基于关键词匹配和流式语义嵌入的意图驱动预热，在 LLM token 生成过程中识别即将到来的工具调用并提前启动沙箱；基于沙箱依赖图的上下文感知随机预取，概率性预测未来沙箱切换；以及语义结果缓存和零拷贝共享内存传输。在高并发多轮 Agent 负载上，SpecBox 将 P99 端到端延迟降低 2.9 倍，峰值内存消耗降低 45.9%。
亮点: 将推测执行思想从 token 层拓展到 Agent 沙箱调度层，用"推测预热+概率预取"破解分离式沙箱的冷启动与内存矛盾。

五、Vibe Coding 最佳实践

实践：手动重打 LLM 生成代码，用物理摩擦消除认知负债
来源: https://ankursethi.com/blog/prevent-cognitive-debt-by-manually-retyping-llm-generated-code/
问题描述: 开发者用 AI 编码助手快速生成大量代码，虽然效率提升了，但如果不仔细审查每一行，会积累大量"认知负债"——你不理解自己代码库中的关键逻辑，一旦出问题无从下手。而逐行审查 AI 的 PR 又枯燥痛苦，难以坚持。
具体做法: 在所有项目的 agents 配置文件中加入固定指令：永远不要自行创建、编辑或删除文件，而是在聊天中展示完整的代码差异，让开发者手动逐行敲入编辑器。不要自动执行修改文件的命令，而是把命令显示出来让人手动执行。这样做虽然比让 AI 直接改文件慢，但开发者在敲入每一行时会自然构建起对代码的心智模型和空间地图——知道每段功能在哪里、怎么工作。一旦遇到不理解的地方可以随时停下来查阅或追问。这种"物理摩擦"让 AI 编码的速度优势得以保留，同时避免了对生成代码的盲目信任。
