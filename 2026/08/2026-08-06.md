一、推理服务相关学术论文

Heterogeneous LLM Serving with General-Purpose Processing-Near-Memory for Retrieval-Based Sparse Attention
论文链接: https://arxiv.org/abs/2608.03555
发布时间: 2026-08-04
类别: cs.AR
论文总结: 前沿 LLM 普遍采用检索式稀疏注意力服务百万级 token 上下文，但解码阶段的 KV cache 读取仍是瓶颈。本文提出异构解码服务系统：GPU 节点持有模型权重并执行投影与 MoE 层，处理近内存（PNM）节点持有 KV cache 与索引并执行所有读取操作。作者论证既有 PIM/PNM 设计的假设已不再成立，由此推导出四项设计需求，并提出 KARAT——结合大容量 LPDDR 与面向检索索引的通用算力的 PNM 设计。配合 OFMS 微批调度隐藏专家 all-to-all、CMR 上下文长度均衡，在三个前沿模型和真实 agent 负载下，吞吐/TDP 较纯 GPU 基线提升 2.09 至 6.13 倍，训练免稀疏注意力方法也有 1.36 至 3.21 倍提升。
亮点: 把 KV cache 整体迁出 GPU、由通用 PNM 节点按需服务稀疏检索，为百万 token 上下文推理提供了一条超越纯 GPU 堆叠的硬件路线。

二、KV Cache 复用相关学术论文

Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for Prefill Reuse
论文链接: https://arxiv.org/abs/2608.03893
发布时间: 2026-08-04
类别: cs.LG
论文总结: 生产部署常在同家族不同规模模型间切换（成本质量分级、对话中途切换、路由），每次切换接收方都要重做 prefill。本文提出跨模型 KV cache 迁移：接收方直接复用源模型 KV，跳过 prefill。作者发现匹配 KV 头数与维度的跨模型 KV 具有显著线性结构，据此设计闭式 ridge 映射器：按 head 操作，先选取最具预测力的若干源层拼接，再去除 RoPE 使拟合位置无关、可跨长度复用，最后在 500 条 FineWeb-Edu 序列上校准。在三个家族六对模型上，线性映射在四对上保留 73% 至 98% 的独立 prefill 精度，另两对需非线性 MLP 补救。映射速度比重做 prefill 快 2.7 至 25 倍，且在多轮交接中保持稳定。
亮点: 用一个可离线校准的闭式线性映射，让同家族模型切换时 KV cache 直接复用、免重做 prefill，兼顾速度与多轮稳定性。

三、推理 Infra 相关学术论文

An Internet for the KV Cache: Rethinking Classical Infrastructure Boundaries in the LLM Inference Age
论文链接: https://arxiv.org/abs/2608.01526
发布时间: 2026-08-02
类别: cs.NI
论文总结: LLM 推理已成为横跨 agent、检索、工具调用、代码执行与多模态的全球异构负载，重叠输入天然支持上下文复用，为存储和复用 KV cache（而非重算）创造了巨大机会。但模型侧压缩 KV 与系统侧降本的技术在传统云边界内各自演进。本文主张未来推理基础设施应允许计算与 KV cache 存储跨云、跨数据中心解耦：网络成为主动分发渠道，带宽、延迟与定价直接决定 KV cache 管理策略。作者提出"KV cache 互联网"愿景，将 KV cache 管理视为内容分发系统，存储与重算决策由模型、基础设施与应用指标共同驱动，实现自适应的延迟与成本最优。
亮点: 把 KV cache 管理类比为 CDN，提出跨云跨数据中心的计算与存储解耦架构，为推理基础设施的长期演进指明方向。

五、Vibe Coding 最佳实践

实践：别当 AI 输出的"传声筒"，review 环节要用自己的话验证
来源: https://gruhn.me/blog/2026-08-03/
问题描述: 在 vibe coding 流程中，开发者很容易把工单描述直接粘给 Claude Code 生成代码，review 反馈来了再原样转给 AI，自己几乎不看代码也不读 AI 的输出。这种做法看似高效，实则让评审者用 Claude Code 完成了实现，而提交者沦为"肉代理"——AI 输出冗长、常有看似合理实则错误的表述，盲目转达不仅没有增值，还把风险和误解层层放大。
具体做法: 拿到 AI 输出后，不要原样转发，而要先读、理解、验证，再用自己的话复述结论或写回复——这本身就是"你已做过前三步"的凭证。在代码 review 中尤其重要：逐行审阅 AI 生成代码，遇到 jargon 密集或看不懂的表述先查证再采纳，对关键改动亲自核对逻辑；把"提出问题、验证答案、转化为自己的判断"当作不可省略的一环，而非把 AI 当成可以直接背书的权威。
