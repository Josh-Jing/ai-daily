Elastic KV Cache for LLM Serving: A Working Reclamation Mechanism, and Why Chunked Prefill Already Closes the Gap
论文链接: https://arxiv.org/abs/2608.23658
发布时间: 2026-08-24
类别: cs.AR / cs.AI
论文总结: 推理引擎启动时按最坏情况为 prefill 激活预留显存，解码为主的阶段这块预留闲置却无法归还给 KV 池。本文实现弹性 KV 缓存：借助调度器对下一批次的预判，在解码期把预留借给 KV 池、prefill 前归还，纯用户态实现于 CUDA 虚拟内存路径，毫秒级解映射、几十毫秒重映射，兼容 CUDA graphs 与前缀缓存。但作者诚实地报告了否定结论：只有当小 prefill 分块严重拖慢首 token 延迟时才有收益，而实测 8192 与 32768 分块的 TTFT 中位数仅差约 1%，直接调低 max_num_batched_tokens 就能以几乎相同延迟换回更多 KV；预留占比还随张量并行从 TP1 的 16% 稀释到 TP4 的 2.7%。
亮点: 把机制做出来再推翻自己的前提，讲清楚显存预留何时值得回收、何时不值得。

论文总结: 注意力与 FFN 分离部署让 MoE 专家权重常驻高带宽 FFN 池成为可能，但解码 SLO 限制运行批次，稀疏路由又扩大激活专家并集，权重读取难以摊销，路由偏斜还会让冷专家资源闲置。本文提出 ReRAM 近存架构，将专家权重留在本地高带宽读之后，通过有界的核内多播池化、共激活感知放置与负载感知取回来恢复占用率，并按诱发需求为各级通信定容。在 Qwen3.5-35B-A3B、Qwen3.5-397B-A17B 与 GLM-5.2 上的实测加建模显示，side-4 池化把占用率从 0.328 提到 0.519，等峰值算力下每 token FFN 池延迟较 H20 降 9.5 倍、权重搬运能耗降 20 倍；H20 注意力加 ReRAM FFN 的系统把解码 TPOT 再降 1.25 至 10.4 倍。

五、Vibe Coding 的 Nice Practice
实践: 用 Rudder 把会话历史反推成规格文档，让测试覆盖率变成规格完整度的度量
来源: https://github.com/RudderCode/Rudder
问题描述: Vibe coding 时 Agent 总在猜测用户想要什么：要么预先写很长的规格文档代价太高，要么任由 Agent 自由发挥，产出的代码偏离意图且难以审查；规格写得多细才算够，一直没有可验证的答案。
具体做法: 安装 Rudder（Claude Code 与 Codex 的本地插件），它在会话结束时读取提示历史与分支中已有规格，反向生成一份最大完整度的规格文档；接着要求 Agent 重写单元测试，每条测试必须对应规格中的一条需求，跑出覆盖率百分比，即你的决策覆盖了多少生成代码；Rudder 再针对未覆盖部分向你提问，走红绿测试驱动流程补齐规格，直到覆盖率达标。规格不再靠感觉写，而是由覆盖率证明它足够全面。
