一、推理服务相关学术论文

OpScale: Operator-level Provisioning and Autoscaling for LLM Serving
论文链接: https://arxiv.org/abs/2608.13499
发布时间: 2026-08-13
类别: cs.DC
论文总结: 云 GPU 集群服务 LLM 需在满足 TTFT 等严格 SLO 的同时控制成本，而自动扩缩容的关键设计问题是"以什么为扩缩单元"。现有方案把整个模型当作单一单元，捕捉不到推理负载的细粒度动态，突发流量下不是违反 SLO 就是 GPU 空转。本文刻画了推理各算子间的显著异质性，据此提出算子级编排框架 OpScale，统一覆盖剖析、供给、放置与运行时服务，并化解细粒度操作带来的组合空间爆炸。生产迹线评估（最多 40 张 A100 与 24 张 GB200）显示，其满足 SLO 的同时最多省 36.3% GPU 与 28% 功耗，固定成本下吞吐提升 44%。
亮点: 把扩缩容粒度从"整个模型"下沉到"算子级"，论证算子弹性是比模型级更优的 scaling 原语。

二、KV Cache 复用相关学术论文

vToken: Token-Level Virtualization for Reclaimable KV Caches
论文链接: https://arxiv.org/abs/2608.13263
发布时间: 2026-08-13
类别: cs.AI
论文总结: KV cache 随序列长度与批大小增长，是 LLM 服务的内存瓶颈。PagedAttention 用固定大小内存块减少了分配器级碎片，但 H2O 等驱逐算法工作在比块更细的 token 粒度，块内碎片使大量已分配的 KV 内存既无法复用也难以回收。本文提出轻量 token 级虚拟化层 vToken：以 token 表间接寻址解耦逻辑 token 存活与物理块放置，再异步重打包存活 token 完成物理回收，且保持 PagedAttention kernel 与 CUDA Graph 兼容。在 vLLM 中实现后，每请求保留 KV 块减少 27.2% 至 72.3%，SLA 约束下吞吐最高提升 1.37 倍，并发上限最多翻倍，驱逐策略接入代码从 500 余行缩至 50 行以内。
亮点: 用操作系统式的虚拟化思路弥合"token 级驱逐"与"块级内存管理"的粒度错配，让驱逐后的内存空洞真正可回收复用。

三、推理 Infra 相关学术论文

HBF Sucks! A Full-Stack Characterization of High-Bandwidth Flash for KV-Centric LLM Serving
论文链接: https://arxiv.org/abs/2608.11668
发布时间: 2026-08-12
类别: cs.AR
论文总结: 更快的存储设备理应让服务更快，本文实测却相反。高带宽闪存 HBF 在封装内以宽接口堆叠 NAND，承诺闪存级容量与远低于 SSD 的读延迟和更高带宽。作者将其直接替换进 Mooncake 式 KV 卸载栈，用扩展 TokenSim、四段两小时 Qwen-Bailian 生产迹线、五个 Dense/MoE 模型与 H100/B200 画像测量：端到端平均延迟反升 2 至 5.5 倍，最大 SLO goodput 下降 1.1 至 2.7 倍。成本收益模型揭示了原因：只有读 I/O 成瓶颈、读多于写、带宽可持续时，更快的远端层才划算，而瞬时 KV 三条全违反；经封装买闪存还挤占 GPU 近层容量，写重流使叠层提前触发热极限。结论是 HBF 不适合当瞬态 KV 的 SSD 替身，配合复用感知放置、写预算与热协调才有价值。
亮点: 用全栈实测戳破"更快存储等于更快服务"的直觉，给出新存储介质接入 KV 卸载栈前必须核对的三条判据。

五、Vibe Coding 最佳实践

实践：给编码 Agent 加一条自我改进反馈回路
来源: https://www.flourish.org/2026/08/personal-apps/
问题描述: 长期用 AI Agent 迭代同一个项目时，同类障碍会反复出现：快照不稳定、依赖目录反复变动、性能问题、缺少工具等。Agent 每次都要重新绕一遍弯路，开发者也被迫反复口头纠正，效率随项目规模增大而持续衰减。
具体做法: 在 AGENTS.md 中写入固定指令：凡是让 Agent 卡住或出错的问题，一律记入 SELF-IMPROVE.md 并累计同一问题的出现次数；开发者定期审查该文件，把高频问题固化成工具、脚本或规范并排期修复。作者实践一个月即自动揪出快照抖动、node_modules 变动、性能隐患等多类反复出现的问题。再配合 plans/ 目录先设计后实现、TODO 文件管理 QA 清单、严格类型检查与全量快照测试，Agent 便拥有稳定反馈回路，几乎每次改动都不再破坏既有功能。
