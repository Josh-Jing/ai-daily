## 一、推理服务相关学术论文

### SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

- **论文链接:** [https://arxiv.org/abs/2607.28150](https://arxiv.org/abs/2607.28150)
- **发布时间:** 2026-07-30
- **类别:** cs.DC

**论文总结:**

当前主流的 LLM 服务系统普遍采用 Prefill-Decode 分离架构，将预填充和解码阶段部署到不同节点上。然而，这种架构在自托管云实例场景下面临严峻挑战：预填充阶段产生的海量 KV Cache 需要在节点间传输，极易耗尽有限的节点间网络带宽。本文提出 SmartGen，一种通过选择性传输关键 KV Cache 条目来缓解网络瓶颈的方案。SmartGen 设计了三条数据传输路径：(1) 基于性能分析的主主动传输路径，在预填充阶段识别并推送关键 KV 条目到解码节点；(2) 并行按需传输路径，在解码阶段同时获取远程和本地 KV 条目；(3) 推测性传输路径，最终将所有 KV Cache 传送到解码节点。实验表明，SmartGen 将 time-to-second-token 最多降低 4.3 倍，同时保持相当的后续解码性能和精度。

**亮点:** 通过"选择性 KV 传输"替代"全量传输"，在不损失精度的前提下将分离式推理的跨节点传输开销降低数倍。

## 二、KV Cache 复用相关学术论文

### SemPIC: Learning Semantic Position-Independent KV Caches

- **论文链接:** [https://arxiv.org/abs/2607.28069](https://arxiv.org/abs/2607.28069)
- **发布时间:** 2026-07-30
- **类别:** cs.AI

**论文总结:**

长上下文检索和 Agentic 工作负载经常在不同指令、历史记录和文档顺序下重复使用相同的文档。前缀缓存（Prefix Caching）无法利用这种复用，而位置无关缓存（PIC）因独立编译的 KV 状态缺乏未来消费时的上下文而不够可靠。本文提出 SemPIC，通过训练一个启用 LoRA 的 Writer 模块来编译原生的逐层文档 KV，同时保留预训练解码器作为不变的 Reader。适应性仅限于离线缓存构建阶段，不改变标准 KV 接口和缓存命中解码路径。此外，论文还提出 KV Gradient Checkpointing 技术，在不切断缓存 KV 梯度的情况下减少峰值训练内存。在三个模型和四个任务上，SemPIC 将平均 micro-F1 从 KV Packet 的 0.53 提升至 0.60，接近完全重计算的 0.62。

**亮点:** 首次实现"语义级"位置无关 KV Cache，使文档 KV 可跨不同上下文复用，逼近全量重计算质量。

## 三、推理 Infra 相关学术论文

### Beyond Prefill-Decode Disaggregation: Dissecting LLM Inference for Heterogeneous Platforms via Dynamic Operator Scheduling

- **论文链接:** [https://arxiv.org/abs/2607.25498](https://arxiv.org/abs/2607.25498)
- **发布时间:** 2026-07-28
- **收录:** MICRO 2026
- **类别:** cs.AR
- **代码:** [https://github.com/YIAI-02/TriForm](https://github.com/YIAI-02/TriForm)

**论文总结:**

Prefill-Decode 分离（PD）和基于 Roofline 的算子放置是跨异构系统划分 LLM 推理的常用策略，但在实践中常常不足。端到端延迟还取决于工作负载形态、运行时设备争用和持久化权重布局。本文提出 DOPS（Dynamic Operator Scheduling），一个硬件感知的闭环框架，联合优化算子调度和块级权重布局。DOPS 构建阶段感知的有向无环图（DAG），集成两个组件：用于动态算子到设备放置的 Bifocal 调度器，以及在严格内存约束下选择硬件高效权重布局的 Weight Layout Arbiter（WLA）。在结合 NPU 和存内计算（PIM）设备的代表性异构系统上，Bifocal 相对 PD 基线实现了 1.20× 至 2.23× 的几何平均加速，WLA 在 Bifocal 基础上提供额外 1.28× 至 1.33× 的加速。

**亮点:** 超越传统 PD 分离范式，通过动态算子调度+权重布局联合优化，在异构硬件上实现显著推理加速。

### 3. OpenLake：开源 KV Cache 卸载存储引擎，长上下文推理成本降低 50%

- **来源:** [GitHub / Hacker News](https://github.com/openlake-project/openlake)
- **时间:** 2026-07-26

**内容摘要:**

OpenLake 是一个高性能开源存储引擎，用于将 LLM 的 KV Cache 从 GPU 内存卸载到共享的 RAM 和 NVMe 层。单个 256K token 的对话（Gemma 4 31B）会产生约 43GB 的 KV 状态，超过 H100 80GB 内存的一半。OpenLake 采用自研 CUDA 内核实现延迟物化（Deferred Materialization），在 KV 块离开 GPU 前进行无损压缩（1.72× 压缩比），在 H100 上实现约 600GB/s 解压吞吐，使 50GB/s 物理链路上的有效 KV 吞吐达 80GB/s。在 128K 上下文下，检索缓存 KV 将 TTFT 从 44 秒降至 0.6 秒（66× 提升），整体 GPU 时间减少 48.2%。项目提供 vLLM 和 SGLang 连接器，使用 Rust 编写并基于 io_uring。

## 五、Vibe Coding 最佳实践

### 实践：区分 Vibe Coding 与 Agentic Engineering 的使用边界——用"受伤者"测试决定代码审查深度

- **来源:** [Simon Willison's Weblog](https://simonwillison.net/2026/May/6/vibe-coding-and-agentic-engineering/)

**问题描述:**

随着 AI 编码工具（如 Claude Code、Codex CLI）越来越可靠，开发者面临一个两难：什么时候可以"放手让 AI 写、不看代码"（vibe coding），什么时候必须严格审查每一行（agentic engineering）？盲目 vibe coding 生产代码速度快但质量不可控；过度审查则无法发挥 AI 的效率优势。

**具体做法:**

Simon Willison 提出一个简单但强大的判断标准——**"谁会因 bug 受伤？"**

1. **个人工具（只有你自己会受伤）→ 放手 vibe coding。** 如果是一个个人脚本或原型，bug 只影响你自己，那就大胆地让 AI 写，不逐行审查，快速迭代。出了问题再告诉 AI 让它修。
2. **面向他人的生产系统（别人会受伤）→ 必须用 Agentic Engineering。** 对生产代码，每一条 AI 生成的逻辑都需要人工审查，并配合自动化测试、文档和安全检查。
3. **中间地带——"验证边界，信任内部"：** 对于确定性高的任务（如"写一个 JSON API endpoint，跑一个 SQL 查询，返回 JSON"），可以信任 AI 的实现，但必须确保它写了自动化测试和文档，用测试来替代逐行审查。这是 Simon 自己的实践："我知道它不会搞砸这个，但我会确保它添加了测试和文档。"

核心原则：**不要在生产代码中跳过质量保障环节，但可以用测试覆盖率来替代逐行代码审查，从而在安全的前提下释放 AI 的速度优势。**
