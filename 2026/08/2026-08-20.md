二、KV Cache 复用相关学术论文

Bounded-State Restoration: Decoupling Local Restore Capacity from External LLM State
论文链接: https://arxiv.org/abs/2608.17826
发布时间: 2026-08-18
类别: cs.DC
论文总结: 分层 KV 缓存系统可将长上下文 LLM 状态保留到 GPU 显存之外，但保留容量并不决定让状态重新可执行所需的本地内存。论文分离出"恢复工作集"（RWS），提出 BSR 方法：先探测完整可复用前缀但不一次性载入 L1，再通过至多 W 个块的窗口逐段确认安装，峰值恢复容量为 O(W) 而总传输量保持 Θ(|S|)。在 DeepSeek-V4-Flash TP=2 双节点上，外部状态增至 31.3 GiB/rank 时 L1 RWS 仅 500.75 MiB/rank，比值达 63.96 倍；SSD 优化将 512K 恢复 TTFT 从 43.1 秒降至 17.6 秒。
亮点: 首次将"发现可复用前缀"与"本地驻留安装"解耦，用 O(W) 有界窗口恢复任意大的外部 KV 状态。

五、Vibe coding 最佳实践

实践: 用 PRD 定义清晰意图，别让 AI 猜你想建什么
来源: https://www.softr.io/blog/vibe-coding-best-practices
问题描述: Vibe coding 中最常见的失败是意图不清晰——开发者凭感觉向 AI 描述需求，AI 生成代码后才发现方向偏离，反复返工。没有明确的需求文档，AI 工具会引导项目陷入无休止的功能蔓延和架构混乱，最终不知道何时才算完成。
具体做法: 在动手 prompt 之前先写一份简短的产品需求文档（PRD），哪怕只是一页 Notion 或 Google Docs 大纲。PRD 需覆盖三个基本点：建什么（如"物业管理者追踪维修请求的客户门户"）、给谁用（如"内部团队负责人和外部供应商"）、怎么运作（如"Google Sheets 数据实时同步，按角色控制访问"）。可先用 ChatGPT 起草初版 PRD 再手动修正。明确"什么"和"为什么"后，AI 就能更有效地处理"怎么做"，大幅减少方向偏离和返工成本。
