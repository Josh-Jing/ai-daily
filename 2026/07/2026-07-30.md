## 1. 推理服务相关学术论文

### SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

- 论文链接: https://arxiv.org/abs/2607.28150
- 发表时间: 2026年7月30日
- 类别: cs.DC（分布式、并行与集群计算）

**论文总结:**

Prefill-Decode 分离架构已成业界主流，但它在自托管云实例上带来一个棘手问题：prefill 节点要把巨大的 KV cache 传给 decode 节点，很容易打满有限的节点间网络带宽。作者在阿里云 L20 GPU + 25Gbps RDMA 的实测中发现，传输 48K token 的长上下文 prompt，KV 传输耗时是 prefill 计算本身的 6.5 倍——网络成为分离架构落地的真正瓶颈。

SmartGen 的思路是不再全量传输 KV cache，而是「选择性地」只传关键 KV 条目。它设计了三条数据传输路径协同工作：(1) 基于 profiling 的主动传输路径——在 prefill 阶段就识别并推送关键 KV 到 decode 节点；(2) 并行按需传输路径——decode 阶段同时拉取远端和本地 KV 条目；(3) 推测传输路径——最终把剩余全部 KV 补传过去。三条路径解决了「prefill 阶段如何精准选 KV」和「decode 阶段如何高效取 KV」两大挑战。实验显示，相比全量 KV 传输，SmartGen 将 time-to-second-token 最高降低 4.3 倍，且后续 decode 性能与精度基本持平。

**亮点:** 首次针对「云实例带宽受限」这一自托管场景的真实痛点，用「选择性 KV 传输 + 三路协同」替代全量传输，让分离架构在普通云 GPU 上也可落地。

## 2. KV Cache 复用相关学术论文

### SemPIC: Learning Semantic Position-Independent KV Caches

- 论文链接: https://arxiv.org/abs/2607.28069
- 发表时间: 2026年7月30日
- 类别: cs.AI（人工智能）

**论文总结:**

长上下文检索和 Agentic 工作负载会反复复用同一批文档，只是指令、历史和文档顺序不断变化。前缀缓存（prefix caching）无法利用这种复用，因为复用内容不在相同前缀之后；而位置无关缓存（PIC）虽然更通用，但单独编译的 KV 状态缺乏未来上下文信息，拼接后质量会崩塌——位置对齐了，上下文却不完整。

SemPIC 的核心是「适配文档表示本身」。它训练一个启用 LoRA 的 Writer，通过行为蒸馏（behavioral distillation）来编译原生的逐层文档 KV，同时保持预训练解码器作为不变的 Reader。所有适配都限定在离线缓存构建阶段，不改变标准 KV 接口和缓存命中后的解码路径。此外还提出 KV Gradient Checkpointing，在不切断 cached KV 梯度的情况下降低峰值训练显存。在三个模型、四个任务上，SemPIC 将平均 micro-F1 从 KV Packet 的 0.53 提升到 0.60，逼近全量重算（Full Recompute）的 0.62。

**亮点:** 指出 PIC 失效的根因不只是位置，还有「上下文缺失」，并用「只训练 Writer、冻结 Reader」的离线蒸馏方案在精度上逼近全量重算，同时保持推理时的标准 KV 接口不变。

## 3. 推理 Infra 相关学术论文

### Beyond Prefill-Decode Disaggregation: Dissecting LLM Inference for Heterogeneous Platforms via Dynamic Operator Scheduling

- 论文链接: https://arxiv.org/abs/2607.25498
- 发表时间: 2026年7月28日（被 MICRO 2026 接收）
- 代码: https://github.com/YIAI-02/TriForm
- 类别: cs.AR（硬件架构）

**论文总结:**

Prefill-Decode 分离（PD）和基于 roofline 的算子放置是跨异构系统切分 LLM 推理的常见策略，但在实际中往往不够用——端到端延迟还取决于负载形状、运行时设备争用和持久的权重布局。本文提出 DOPS（Dynamic Operator Scheduling），一个硬件感知的闭环框架，联合优化算子调度和分块权重布局。

DOPS 构建阶段感知的有向无环图（DAG），集成两个组件：(1) Bifocal 调度器——动态决定算子到设备的放置；(2) Weight Layout Arbiter（WLA）——在严格显存约束下选择硬件高效的权重布局。在结合 NPU 和存内计算（PIM）设备的代表性异构系统上，Bifocal 相对 PD 基线取得 1.20× 到 2.23× 的几何平均加速；WLA 在此基础上再叠加 1.28× 到 1.33× 的加速。DOPS 还支持系统性地分析 LLM 服务的工作负载敏感性和硬件可扩展性。

**亮点:** 跳出「只做 PD 分离」的框架，把算子级动态调度与权重布局联合优化，证明在异构硬件上单纯 PD 分离远非最优，为边缘/异构推理 infra 提供了新的设计维度。

## 5. Vibe Coding Nice Practice

### 上下文预热（Context Priming）：每次会话前先喂上下文

来源: Kunal Ganglani《Vibe Coding Best Practices in 2026》（2026年7月更新）

**问题:** 每次 Claude Code / Cursor 会话开始时，AI 对你的项目一无所知。如果不做任何上下文准备就直接提需求，AI 只能靠猜测你的命名规范、数据结构和架构模式来生成代码——结果往往与现有系统格格不入。据 Vibe Code Wiki 的分析，缺乏上下文预热时，标准 CRUD 功能的开发速度慢 2-5 倍，样板代码多出 40-60%。

**具体做法:**

1. 在项目根目录维护一个活的 CLAUDE.md（或等价配置文件），会话启动时自动加载并全程保持在上下文中。
2. 文件内容包含：技术栈、关键架构决策、命名规范，以及——最关键的——一份「不要做」清单（don't list）。实践表明，这份「不要做」清单比「要做」清单省下的返工更多。
3. 随着项目推进持续往里追加约束。每一次痛苦的调试都应沉淀为一条新的约束文档。
4. 配合「迭代脚手架」而非一次性生成：先搭骨架→review→commit，再逐个功能填充，每步都是可 review、可回滚的最小单元。

配套的安全习惯：在每个 prompt 中显式写入安全约束（参数化查询、输入校验、禁用 eval、遵循 OWASP Top 10），因为 Cloud Security Alliance 2026年4月的报告显示，AI 辅助开发者提交安全漏洞的速率是同行的 10 倍。

Pinecone 推出 Nexus 知识引擎的公开预览版，定位为 AI Agent 专用的知识基础设施。传统 RAG 在 query 时才教 Agent 去哪找信息，而 Nexus 在数据「策展」阶段就把原始文档转化为结构化的知识制品（knowledge artifacts），让 Agent 在需要时直接获取已组织好的领域知识。
