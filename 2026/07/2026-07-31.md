## 1. 推理服务相关学术论文

### ConServe: Observation, Not Prediction — Conversation-Level Disaggregated Scheduling for Agentic Serving

- 论文链接: https://arxiv.org/abs/2606.01839
- 发表时间: 2026年6月

**论文总结:**

本文针对 LLM Agent 多轮调用场景下的推理服务调度问题提出了 ConServe 系统。现有服务系统以单轮请求（turn）为调度单位，对每一轮独立决定是否做 prefill-decode 分离，而这个决策依赖于解码长度、工具调用行为、KV 增长等无法在调度时刻观测到的量，只能靠预测——预测不准则调度次优。

ConServe 的核心洞察是：将调度单位从「单轮」提升到「整个对话」（conversation），就能把单轮级别的不规则性转化为稳定的两阶段结构——(1) 第一轮的 compute-bound prefill，(2) 之后漫长的 memory-bound 尾部。因此路由决策只需读取第一轮输入长度和每解码步的 KV 占用，两者均可直接观测，无需任何预测模型。

ConServe 将第一轮 prefill 路由到高吞吐 prefiller，KV cache 仅传输一次，然后将整个对话固定在单个 decoder 上运行其全部尾部。实验显示：相比逐轮预测基线，p95 time-to-first-effective-token（对话首个用户可见输出的延迟）降低 51.08%，能效提升 7.51%，映射到异构 GPU 层级后能效再提升 22.75%。

**亮点:** 首次提出 TTFET（Time-to-First-Effective-Token）指标，反映用户真正关心的对话级响应延迟，而非单轮延迟。核心思想是「观测而非预测」，用提升调度粒度的方式消除预测依赖。

## 2. KV Cache 复用相关学术论文

### C²KV: Compressed and Composable KV Cache Reuse for Efficient LLM Inference

- 论文链接: https://arxiv.org/abs/2607.17715
- 发表时间: 2026年7月（被 ACM SIGKDD 2026 接收）
- 代码: https://github.com/s7a9/C2KV

**论文总结:**

长上下文推理是 RAG 等 LLM 应用的核心场景，KV cache 的存储和访问成本成为关键瓶颈。已有非前缀 KV cache 复用方法主要关注节省计算，忽略了存储成本；而将 KV 压缩与非前缀复用直接组合会导致严重的精度下降。

C²KV 提出了一个统一框架，联合优化 KV cache 压缩和拼接。核心设计包括：

1. 轻量级 sidecar Extractor，使用可学习的压缩 token 和结构化注意力流，生成位置无关（position-agnostic）的模块化 KV 表示，可灵活复用和拼接，且不修改冻结的基座模型。
2. 压缩-拼接协同训练策略，使提取时的表示与下游复用行为对齐。

实验在多个长上下文基准和模型族上验证，C²KV 显著降低了 KV cache 存储和传输成本，在长上下文场景下实现最高 17 倍推理加速，同时保持生成质量。

**亮点:** 首次将 KV 压缩与非前缀复用统一到同一框架，解决了两者朴素组合导致的精度崩塌问题。学习到的 KV 表示天然位置无关，实现了真正的模块化拼接。

## 3. 推理 Infra 相关学术论文

### Beyond the Buzz: A Pragmatic Take on Inference Disaggregation

- 论文链接: https://arxiv.org/abs/2506.05508
- 发表时间: 2025年6月

**论文总结:**

推理分离（Disaggregation）将 LLM 推理拆分为 prefill 和 decode 两个阶段部署到不同计算池，在 2025 年成为业界默认架构。本文对分离式推理进行了务实的系统分析，聚焦于吞吐量（摊销成本）和交互性（服务质量）的 Pareto 前沿。

论文在 Blackwell 系统 + FP4 精度的现代推理基础设施上进行了模拟分析，核心发现：

1. 分离式架构的主要性能增益来自为 prefill 和 decode 分别使用不同的模型并行策略，各自独立优化 SLA。
2. 扩展和速率匹配是关键挑战：prefill 和 decode 池需要独立配置 GPU 数量和并行度，且需要处理两阶段之间的 KV cache 传输。
3. 尽管行业热情高涨，分离式服务的大规模实际部署仍然有限，主要受限于优化搜索空间的复杂性和系统级协调的难度。

论文指出，分离不仅是「拆分」，更是一种可组合的系统架构——它为跨推理栈各层级的专门优化打开了新空间：针对不同阶段的硬件调优、KV cache 存储改进、网络通信开销降低、以及更低延迟的 KV 传输。

**亮点:** 不盲目吹捧分离架构，而是量化分析了其在现代 Blackwell 硬件上的实际收益和部署瓶颈，为工程落地提供了设计空间导航。

## 5. Vibe Coding Nice Practice

### 状态块架构：对抗上下文腐烂的可操作方案

来源: Reddit r/vibecoding 社区实践总结

**问题:** Vibe coding 时随着对话变长，模型注意力被稀释在庞大的 KV cache 上，出现「上下文腐烂」（context rot）——即使有 1M token 窗口，"lost in the middle" 问题依然存在，如果系统提示是单体大块则更严重。

**实践:**

1. 使用 `<governance>` XML 标签包裹核心指令，形成「状态块」架构，而非把 50+ 条指令塞进一个 prompt 块。
2. 每隔 10 轮对话，强制模型输出 `<session_summary>` JSON，摘要当前状态。
3. 将摘要注入下一轮对话，保持关键上下文不被稀释。
4. 配合「先规划再编码」原则：先与 Agent 迭代完善计划文档，再开新对话执行——避免在代码中迭代，而在计划中迭代。

**配套习惯:** 每次 Agent 运行前做 `git commit` 本地备份 + 时间戳 zip 副本；遇到 bug 时开新对话让 Agent「只诊断不修复」，并行跑 2-3 个 Agent 看是否收敛到同一诊断，确认后再动手。
